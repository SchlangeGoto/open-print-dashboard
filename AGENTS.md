# AGENTS.md

OpenPrintDash — a self-hosted Bambu Lab dashboard. AGPL-3.0.

## Repository state

`main` still uses the old `api/` + `web/` layout. The migration branch and
everything stacked on it use:

- `backend/` — FastAPI, Python 3.13, SQLModel, Alembic, PostgreSQL
- `frontend/` — Next.js 16, React 19, Tailwind, shadcn/ui
- `mobile/` — Expo / React Native
- `site/` — static Next.js marketing site
- `compose.yml` — development Docker Compose stack (source mounts, dev servers)
- `compose.prod.yml` — production Docker Compose stack (built images, no source mounts)
- `compose.ghcr.yml` — production from published GHCR images, with Caddy
- `compose.public.yml` — public site and demo from GHCR images, with Caddy

CI details: `docs/CI.md`. Production deployment: `docs/DEPLOYMENT.md`.

Do not assume every directory exists on every branch. Check with
`git ls-tree --name-only <branch>` before adding files to a branch.

## Commands

Install local hooks once:

```bash
python -m pip install pre-commit
pre-commit install
pre-commit run
```

Backend, from `backend/`:

- `uv sync` — install dependencies
- `uv run bash scripts/prestart.sh` — run migrations + initial data
- `uv run fastapi dev` — dev server on :8000
- `uv run bash scripts/lint.sh` — mypy, ruff check, ruff format check
- `uv run bash scripts/test.sh` — pytest + coverage (needs PostgreSQL)

Frontend, from `frontend/`:

- `npm ci`
- `npm run dev` — demo mode is on by default
- `npm run lint`
- `npm run typecheck`
- `npm run build`
- `npm run test:e2e` — Playwright; build with `NEXT_PUBLIC_DEMO_MODE=true` first

Mobile, from `mobile/`:

- `npm ci`
- `npm run lint`
- `npm run typecheck`
- `npx expo install --check`
- `npx expo export --platform android --output-dir dist-android`

Site, from `site/`:

- `npm ci`
- `npm run lint`
- `npx tsc --noEmit`
- `npm run build` — static export to `site/out/`

Releases:

- `git tag vX.Y.Z && git push origin vX.Y.Z` — publishes GHCR images and EAS
  mobile artifacts through `Release Containers` and `Release Mobile`.
- EAS setup and signing are documented in `docs/DEPLOYMENT.md`.

## Rules

- Use conventional commits: `feat(scope): ...`, `fix(scope): ...`, `chore: ...`.
- Keep PRs small. Aim for under 400 changed lines; review quality drops sharply
  above ~1,000. Split work into stacked PRs instead of one long-lived branch.
- This repo uses stacked PRs. Merge bottom-up. Do not squash the bottom of a
  stack unless you rebase the rest onto `main` afterwards.
- Never commit `.env`, tokens, printer access codes, real serial numbers, or
  anything from `docs/website-research/screenshots/`.
- Keep `.env.example` in sync with new settings.
- Backend model changes require an Alembic migration under
  `backend/app/alembic/versions/`.
- API request/response changes must be reflected in `frontend/` and `mobile/`.
- Run the relevant checks before committing. CI runs them too.
- Local PR review: use the `reviewer` subagent, or `/pr-review <number>` if the
  command is installed in `~/.config/opencode/commands/`. The command is
  intentionally not committed.
- CI review is CodeRabbit (advisory); the deterministic checks are the gate.
  Use `/pr-review` locally for an OpenCode review with your own key/model.
- `frontend/AGENTS.md` is generated by `next dev`. Read it before changing
  Next.js code, and commit it if it changes.
- Review rules live in `.github/REVIEW.md`.
